# Timpson Lyceum — iOS app (SwiftUI)

Native iOS/iPadApp for the Lyceum. Talks to the web app's mobile API
(`edu-web/app/api/mobile/v1/*`) over a Bearer-token flow.

## Open it

The `.xcodeproj` is generated by [xcodegen](https://github.com/yonyz/XcodeGen)
(so it's gitignored — regenerate anytime):

```bash
brew install xcodegen        # once
cd edu-ios
xcodegen generate            # writes Lyceum.xcodeproj
open Lyceum.xcodeproj
```

Then pick a simulator (or your device) and Run. Set your signing Team in
Signing & Capabilities the first time you run on a physical device.

## Point it at a backend

By default it calls production. For local dev against `edu-web`'s `npm run dev`,
edit the scheme (Product ▸ Scheme ▸ Edit Scheme ▸ Run ▸ Arguments ▸ Environment
Variables) and add:

```
API_BASE_URL = http://<your-Mac-LAN-IP>:3000
```

Use the LAN IP, not `localhost` (a device/simulator's localhost is itself).

## Layout

- `project.yml` — xcodegen spec (universal iPhone/iPad, iOS 17+, SwiftData, test target).
- `Sources/` — SwiftUI app.
  - `Networking/` — `APIClient` (async/await + token refresh), `TokenStore` (Keychain).
  - `Auth/`, `Models/`, `Offline/` (SwiftData write queue), `Drills/` (native generators).
  - `Views/` — tabs (Learn/Review/Drills/Profile) + course/lecture/quiz/login screens;
    `WebViews` hosts the YouTube player and the KaTeX/Markdown renderer.
- `Tests/` — XCTest unit tests (`xcodebuild test`, or ⌘U in Xcode).

## Offline

Engagement writes (quiz attempts, review grades, drill sessions, watch progress)
persist to a SwiftData queue when offline and replay on reconnect; each carries a
`clientId` the server dedups. Video playback and KaTeX need a connection.
